# Data Model: Authenticated Sessions and Access Credentials

## Domain: `Session` (new entity)

Infrastructure-independent; no reference to tokens, HTTP, EF Core, or Identity.

| Field | Type | Rules |
|---|---|---|
| `Id` | `Guid` | Stable unique session identifier; generated by the caller (`Guid.NewGuid()`), never `Guid.Empty`. Revocation, audit, and the credential's `sid` link all use this value. |
| `UserId` | `Guid` | The authenticated user; never `Guid.Empty`. |
| `ApplicationId` | `Guid` | The single application the session belongs to; never `Guid.Empty`. |
| `CreatedAt` | `DateTimeOffset` | Server time at creation (UTC). |
| `ExpiresAt` | `DateTimeOffset` | Absolute expiry: `CreatedAt + lifetime`. Fixed at creation; never extended. |
| `RevokedAt` | `DateTimeOffset?` | `null` while not revoked; set once, durable. |

Not modelled (deliberately): last-activity timestamp (sessions do not slide), client/device metadata (no justified need), the access credential or any hash of it (credentials are stateless and not stored).

### Behavior

- `Session.Create(id, userId, applicationId, now, lifetime)`: rejects empty identifiers and a non-positive `lifetime`; sets `ExpiresAt = now + lifetime`.
- `Revoke(now)`: sets `RevokedAt` if still `null`; repeated calls leave the first value untouched (idempotent).
- `GetState(now)`: returns `SessionState`:

| Condition | State |
|---|---|
| `RevokedAt` is set | `Revoked` (takes precedence, even if also past expiry) |
| otherwise `now >= ExpiresAt` | `Expired` |
| otherwise | `Active` |

`SessionState { Active, Expired, Revoked }` is a Domain enum. The *temporal/revocation* state lives in the entity; **eligibility** of the user, application, and membership (the rest of the specification's definition of "Active") is evaluated by `SessionService` against the existing `User`, `Application`, and `ApplicationMembership` entities, because those are separate aggregates. An `Active` `SessionState` therefore never authorizes access by itself.

### State transitions

```text
Active ──(now >= ExpiresAt)──▶ Expired
Active ──Revoke()──▶ Revoked
Expired ──Revoke()──▶ Revoked   (RevokedAt recorded; state reports Revoked)
Revoked ──Revoke()──▶ Revoked   (no change)
```

There is no transition back to `Active`. Loss and regain of user/application/membership eligibility does **not** change the session record (clarification Q2): access is refused while ineligible and works again after reactivation if the session is neither expired nor revoked.

## Persistence: `Sessions` table (new migration `AddSessions`)

| Column | Type | Constraints |
|---|---|---|
| `Id` | `uuid` | Primary key (`PK_Sessions`), value generated by the application |
| `UserId` | `uuid` | Not null |
| `ApplicationId` | `uuid` | Not null |
| `CreatedAt` | `timestamp with time zone` | Not null |
| `ExpiresAt` | `timestamp with time zone` | Not null |
| `RevokedAt` | `timestamp with time zone` | Nullable |

- Foreign key `FK_Sessions_ApplicationMemberships_UserId_ApplicationId` from `(UserId, ApplicationId)` to the existing alternate key `AK_ApplicationMemberships_UserId_ApplicationId`, `ON DELETE RESTRICT` (same pattern as `UserRoles`). A session can only exist for a real user/application membership pair, and membership rows are deactivated rather than deleted, so history remains intact.
- Index `IX_Sessions_UserId_ApplicationId` on `(UserId, ApplicationId)` (supports the foreign key and a future "revoke all sessions of a user" feature, which is not implemented now).
- No other tables change. Identity tables are untouched. No credential, token, or secret is persisted.
- Expired and revoked rows are retained for auditability; purging is out of scope.

## Application layer types (new)

| Type | Kind | Purpose |
|---|---|---|
| `SessionPolicy` | immutable record (`SessionLifetime`, `AccessCredentialLifetime`) | Validated configuration: both `> 0`, access lifetime `<= ` session lifetime. Constructed once at startup. |
| `AccessCredentialClaims` | record (`SessionId`, `UserId`, `ApplicationId`, `IssuedAt`, `ExpiresAt`) | The only data a credential carries. |
| `PublicSigningKey` | record (`KeyId`, `KeyType`, `Curve`, `Algorithm`, `Use`, `X`, `Y`) | Public verification key as plain data for `GET /auth/signing-keys`. |
| `SessionOperationResult` | result class | Success carries `SessionId`, `UserId`, `ApplicationId`, optional `AccessCredential`, `AccessCredentialExpiresAt`, `SessionExpiresAt`; failure carries nothing externally. Internal `SessionRejectionReason`. Used by create, renew, validate, logout. |
| `SessionRejectionReason` | internal enum | `NotAuthenticated`, `MalformedCredential`, `CredentialExpired`, `SessionNotFound`, `SessionRevoked`, `SessionExpired`, `InactiveUser`, `InactiveApplication`, `InactiveMembership`, `ApplicationMismatch`. Never leaves the Application layer; drives logs and security events only. |

### Ports (new, Application-owned)

| Port | Methods | Implemented by |
|---|---|---|
| `ISessionRepository` | `AddAsync(Session)`, `GetByIdAsync(Guid)`, `SaveChangesAsync()` | Infrastructure EF Core repository |
| `IAccessCredentialIssuer` | `Issue(AccessCredentialClaims) -> string` | Infrastructure signed-token adapter |
| `IAccessCredentialValidator` | `ValidateAsync(string, CancellationToken) -> Task<AccessCredentialClaims?>` (`null` = unauthentic or malformed; **does not** judge lifetime) | Infrastructure signed-token adapter |
| `IAccessCredentialKeySet` | `GetPublicKeys() -> IReadOnlyList<PublicSigningKey>` | Infrastructure signing-key service |

Existing ports reused unchanged: `IUserRepository.GetByIdAsync`, `IApplicationRepository.GetByIdAsync`/`GetByCodeAsync`, `IApplicationMembershipRepository.GetAsync`, `ISecurityEventRecorder` (signature extended, below). The existing effective-permission lookup is **not** called by this feature.

### Change to existing contracts

- `ISecurityEventRecorder.RecordAsync(type, userId, applicationId, ct)` gains a `Guid? sessionId` parameter between `applicationId` and the cancellation token (a required parameter, because a C# optional parameter cannot precede the non-optional token). `LoggingSecurityEventRecorder`, the recording test double, and the three existing `LoginService` call sites (which pass `null`) are updated.
- `SecurityEventType` gains: `SessionCreated`, `AccessRenewed`, `SessionRevoked`, `LogoutCompleted`, `AccessRejectedExpired`, `AccessRejectedRevoked`, `AccessRejectedInvalidState`, `AccessRejectedApplicationMismatch`.
- `LoginOperationResult.Success(...)` becomes `internal` so only `LoginService` can mint a successful authentication result.
- `LoginResponse` (API DTO) gains `sessionId`, `tokenType`, `accessToken`, `expiresAt`, `sessionExpiresAt` (additive).

## Access credential (not persisted)

Compact JWS, ES256. Header: `alg=ES256`, `typ=JWT`, `kid=<RFC 7638 thumbprint>`.

| Claim | Value |
|---|---|
| `iss` | Configured issuer (`Sessions:Issuer`, default `gaussauth`) |
| `sub` | `UserId` |
| `aud` | `ApplicationId` |
| `sid` | `SessionId` |
| `iat` | Issue time (Unix seconds, server clock) |
| `exp` | `min(iat + AccessCredentialLifetime, session.ExpiresAt)` (Unix seconds) |

No other claims. In particular: no roles, permissions, email, profile data, password material, security stamp, or business data.

## Validation rules (summary of `SessionService`)

Evaluation order for validate/renew (first failing check selects the internal reason): credential authentic → credential not expired → session exists → token `sid`/`sub`/`aud` equal the session's id/user/application → caller's application (validate only) equals the session's application → session not revoked → session not expired → user active → application active → membership active. Creation applies the user/application/membership checks to the successful authentication result, then writes the session.

## Relationships

```text
User 1 ──── * Session * ──── 1 Application
        (via ApplicationMembership composite key: exactly the pair (UserId, ApplicationId))
```

A user may have many concurrent sessions, including several in the same application; each is independent.
